# ИИ-мастер для ролевых игр — обзор проекта

> Статус: **планирование**. Кода ещё нет. Это набор проектных документов для последующего изучения и выбора решений.

## Что это

Универсальная платформа, где ИИ ведёт настольную ролевую игру (TTRPG) любой системы. Админ загружает правила любой игры — ИИ их изучает, структурирует и потом ведёт партию с живыми игроками. Интерфейс похож на Notion/Obsidian: дерево файлов слева, вкладки и чаты в центре.

## Ключевая идея (одно предложение)

**Платформа ничего не знает о правилах игр — она даёт универсальные примитивы (файлы, чат, рендерер, инструменты), а всю игровую логику проектирует нейронка.**

## Два агента

| Агент | Роль | С кем работает |
|---|---|---|
| **Builder** | Изучает правила, строит структуру мастера (глоссарий, шаблоны, скилы, формулы) | Админ |
| **Game Master** | Ведёт игру, используя структуру от Builder'а | Игроки |

## Три главных принципа

1. **Нейронка = данные и структура, никогда не вёрстка.** Она проектирует листы на языке примитивов; отрисовкой занимается код-рендерер. Один кривой ответ модели не должен ломать интерфейс.
2. **Файлы — источник истины.** Всё игровое состояние в файлах (`.md` + `.yaml`). БД (SQLite) только для пользователей/сессий/авторизации.
3. **Нулевое знание о правилах в коде.** Ни «HP», ни «ход», ни «класс» не зашиты. Всё это создаёт нейронка под конкретную игру.

## Что пишем мы (код-платформа)

- Файловое хранилище с версионированием
- Рендерер Markdown со скрытыми маркерами + сборка composite-документов
- Движок формул (детерминированные вычисления вместо «математики нейронкой»)
- Чат (личный + общий) с кнопками бросков и командами
- Drag-n-drop для инвентаря/слотов
- Набор инструментов (tools) для агентов
- Индексация правил для поиска (полнотекстовый + семантический)
- SQLite для пользователей/сессий

## Что решает нейронка

- Как структурировать правила и глоссарий
- Из каких секций/полей/формул состоит лист персонажа (и любой другой лист)
- Какие мета-данные ей нужны и в каком формате
- Всю игровую логику: проверки, сцены, бой (если он есть), скрытые действия

## Порядок разработки (кратко)

1. **Builder** (просто агент: парсинг + структурирование правил, без UI игрока)
2. Тест Builder'а на реальных правилах
3. Рендерер и отображение
4. **Game Master** (второй агент, игровой процесс)
5. Миграции, шеринг, помощники, тактика, онлайн

Подробнее — в `06-roadmap.md`.
