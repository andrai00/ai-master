# Стратегии работы с данными

## Проблема

Правила игры — сотни страниц. Грузить всё в контекст LLM на каждый запрос: дорого, медленно, нейронка путается. Агент должен **искать точечно** — нужный кусок именно когда потребовался.

---

## Два режима поиска

### Полнотекстовый (`search_content`)

Быстрый grep по файлам. Инструмент: `search_content(query, path?)`.

**Когда:**
- Конкретный термин («что такое тёмное зрение?»)
- Поиск по ключевому слову («скрытность», «яд», «падение»)

**Ограничения:** не понимает синонимы, не понимает контекст.

### Семантический (`semantic_search`)

Поиск по смыслу через эмбеддинги. Инструмент: `semantic_search(query)`.

**Когда:**
- Игрок описал действие не зная термина («хочу тихо пробраться»)
- Сложный запрос («как лечить яды разными способами?»)
- Правила размазаны по разным секциям

**Реализация:**
- Builder при создании глоссария строит индекс: `rules/.index/embeddings.json` + `mapping.json`
- Game Master вызывает `semantic_search` → платформа эмбеддит запрос → ищет ближайшие → возвращает top-N кусков с путями к файлам

Выбор online (OpenAI) vs offline (Transformers.js) эмбеддингов — открытый вопрос (`07-open-questions.md`).

## Progressive disclosure (послойное раскрытие)

Агент не читает весь файл сразу. Идёт слоями от лёгкого к тяжёлому:

### Слой 1: Оглавление (`_index.md`)

Всегда в контексте. Маленький файл — карта всего что есть:

```md
# Глоссарий

## Расы (см. races/)
- Люди → races/human.md
- Эльфы → races/elf.md
- Дварфы → races/dwarf.md

## Классы (см. classes/)
- Воин → classes/fighter.md
...

## Механики (см. mechanics/)
- Бой → mechanics/combat.md
...
```

### Слой 2: Front-matter (TL;DR)

Каждый файл правил начинается с front-matter:

```yaml
---
title: "Эльф"
summary: "Лесная раса. +2 ловк, тёмное зрение, владение луками."
keywords: [эльф, раса, ловкость, зрение, лук]
---
```

Агент читает **только front-matter** релевантных файлов чтобы понять какой открывать.

### Слой 3: Полное содержание

Когда агент определил что файл нужен — читает целиком.

### Слой 4: Связанные файлы

Внутри файла ссылки: `[[mechanics/dark-vision]]`. Агент идёт по ссылкам если нужно.

## Стратегия для Builder'а (изучение правил)

1. **Первый проход — оглавление.** Парсит PDF → ищет/составляет оглавление → показывает админу
2. **Приоритеты.** Что важно немедленно (создание персонажа), что для игры (механики), что отложить (лор)
3. **Посекционный разбор.** Каждую важную секцию: читает → выделяет суть → сохраняет в `rules/<секция>/` с TL;DR → добавляет термины в глоссарий
4. **Вопросы админу.** Противоречия, пробелы, варианты правил — вопрос с вариантами + свой ответ
5. **Составление карты.** Создаёт `rules/_index.md` — полную карту. Этот файл Game Master читает первым всегда

---

## Что в контексте Game Master'а ВСЕГДА

- System prompt
- `rules/_index.md` — карта глоссария (маленький файл)
- Данные листа персонажа игрока с которым общается
- Последние N сообщений чата (скользящее окно)
- Свежий саммари если есть (`state/summary.md`)

## Что загружается ПО ЗАПРОСУ

- Конкретный файл правил (когда игрок спросил или агент понял что нужно)
- Листы других персонажей (только если общая сцена или скрытое действие)
- Логи сессии (если нужно вспомнить)

---

## Алгоритм поиска в глоссарии (Game Master)

```
Игрок: "хочу переплыть реку"
    │
    ▼
Агент: _index.md → "передвижение: mechanics/movement.md"
    │
    ▼
Читает TL;DR mechanics/movement.md:
  "Плавание: проверка Атлетики СЛ 15"
    │
    ▼
Достаточно → отвечает игроку
```

Если TL;DR недостаточно → полный файл.
Если полного файла недостаточно → `semantic_search("плавание в броне")` → связанное правило.

## Контекстное окно: стратегии кэширования

### Скользящее окно

Последние N сообщений в контексте всегда. Остальное — в логах на диске. Если нужно вспомнить — `search_content` по логам.

### Авто-саммари

Каждые ~K сообщений агент пишет саммари "что произошло" в `sessions/<id>/state/summary.md`. При следующем запросе свежий саммари загружается в контекст как замена сырой истории.

### Ручной recall

Игрок: "а что тот NPC говорил про подземелье?" → агент ищет по логам (полнотекстовый или семантический) → находит → отвечает.

## Инструменты поиска (сводка)

| Инструмент | Назначение |
|---|---|
| `search_content(query, path?)` | Полнотекстовый grep |
| `semantic_search(query)` | Поиск по смыслу через эмбеддинги |
| `read_summary(path)` | Только front-matter файла (TL;DR) |
| `read_file(path)` | Полный файл |
| `get_index()` | `_index.md` глоссария |
| `search_logs(query)` | Поиск по логам сессии |
| `summarize_to_state(text)` | Сохранить саммари |

---

## Индексация (делает Builder, пользуется Game Master)

```
rules/
  _index.md           ← оглавление (читается всегда)
  .index/             ← для семантического поиска
    embeddings.json   ← векторные представления секций
    mapping.json      ← {embedding_id → путь к файлу + номер строки}
```

`semantic_search(query)`:
1. Эмбеддит запрос
2. Ищет ближайшие в `embeddings.json`
3. Через `mapping.json` находит пути к файлам
4. Возвращает top-N релевантных кусков
