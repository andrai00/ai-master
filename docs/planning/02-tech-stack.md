# Технологический стек

Проект на Node.js. Здесь — выбор технологий по каждому слою. Ничего ещё не зафиксировано жёстко, это варианты с рекомендациями.

---

## 1. Агентный фреймворк (ядро)

Агентный цикл (ReAct): LLM получает задачу, думает, вызывает инструменты, получает результат, снова думает — пока задача не решена. Нам нужно встроить эту логику, не изобретая цикл с нуля.

### Vercel AI SDK (`ai`) — рекомендуется

- `generateText` / `streamText` + `stopWhen`/`maxSteps` — цикл думай-делай внутри одной функции
- Любые модели (OpenAI, Anthropic, Google, локальные через Ollama)
- Стриминг из коробки
- Tool calling с валидацией через Zod
- Мало абстракций — не навязывает архитектуру

Минусы: нет встроенной памяти и RAG — но нам это и не нужно готовое, у нас своя файловая система и свой поиск.

### Mastra

Надстройка над AI SDK: memory, workflows, evals, встроенный RAG. Плюс — многое готово. Минус — моложе, больше концепций, часть его фич нам не подходит (у нас своя модель хранения).

### LangChain.js

Максимум готовых кубиков (Chains, Agents, Memory, Retrievers, LangGraph). Минус — тяжёлый, много абстракций, легко переусложнить. Оправдан только если понадобятся сложные графы состояний.

### Сравнение

| | AI SDK | Mastra | LangChain.js |
|---|---|---|---|
| Порог входа | низкий | средний | высокий |
| Встроенная память | нет | да | да |
| Стриминг | да | да | да |
| RAG | нет | да | да |
| Workflows/графы | нет | да | да (LangGraph) |
| Зависимости | мало | средне | много |
| Гибкость | высокая | средняя | низкая |

**Вывод:** начать с **AI SDK**. У нас всё равно кастомное хранилище, кастомный поиск и кастомные инструменты — тяжёлый фреймворк только помешает. Если понадобятся сложные workflow — рассмотреть LangGraph точечно.

Не на Node.js (для справки): CrewAI, AutoGen — Python, многоагентные, нам не подходят по языку.

## 2. Формат хранения данных

Все данные хранятся в Prisma + SQLite. Метаданные — колонки таблиц. Тело документов — MD-текст в колонке `content`. Изображения — в БД (base64, для аватаров и небольших артов).

Для характерников (composite-документы) — отдельные связанные таблицы (слои, поля, формулы).

### Почему Prisma
- Схема без потери данных (`prisma db push`)
- Типизированные запросы (автогенерация типов)
- Отношения между таблицами (foreign keys)
- Масштабируемость: 6+ таблиц без ручного SQL

---

## 3. Хранилище состояния

- **Prisma + SQLite** — все данные: пользователи, сессии, правила (MD), листы, чаты, логи, изображения. Один файл `data/ai-master.db`.
- Схема через `prisma db push` — не теряем данные при изменении схемы.
- Метаданные документов — колонки таблиц (type, visibility, tags, section, order).

---

## 4. Движок формул

Нужен детерминированный вычислитель выражений вроде `(STR - 10) / 2 + LEVEL + PROF`. **Нейронка не должна считать математику сама** — только задавать формулы.

Варианты:
- `mathjs` — мощный, поддерживает переменные, функции, единицы. Скорее всего избыточен, но надёжен.
- `expr-eval` — лёгкий парсер математических выражений.
- Свой мини-интерпретатор — если нужны кастомные функции (броски кубов внутри формул, условия).

Требование: поддержка бросков (`1d6+2`), условий (если/иначе), ссылок на другие поля, зависимостей (пересчёт по цепочке). Вероятно понадобится обёртка над `mathjs` + кастомные функции для кубов.

## 5. Рендерер Markdown

Нужен рендер Markdown + расширения (скрытые маркеры, кнопки бросков, слоты инвентаря, подстановка данных).

- Парсер: `remark` / `unified` (AST, легко расширять плагинами) или `markdown-it` (плагины, быстрый).
- `remark`/`unified` предпочтительнее: даёт AST, можно писать плагины для маркеров и композиции слоёв.
- Кастомные узлы: кнопка броска `[🎲 D20+5]`, слот инвентаря, embed другого документа.

## 6. Интерфейс (UI)

- **Next.js 16 + React 19 + Ant Design** — веб-приложение, серверные экшены вместо API-роутов
- **FSD-архитектура** — слои: app-layer, pages-layer, widgets, features, entities, shared
- **i18n** — `react-i18next`, русский + английский
- **Темы** — тёмная/светлая через Ant Design ConfigProvider
- **Адаптивность** — десктоп + мобильная версия
- Обязательно: сайдбар с навигацией, секции, чат-панель с аватарами и кнопками действий, drag-n-drop

---

## 7. Транспорт / сервер

- **Next.js** — встроенный сервер, серверные экшены для всей логики
- API-роуты только для загрузки файлов (>1MB, обход bodySizeLimit серверных экшенов)
- **Socket.IO** — real-time push на том же сервере Next.js (`server.mjs`, WebSocket + long-polling fallback): события, step-прогресс агентов, presence, typing

## 8. Парсинг документов

Для Builder'а — извлечь текст из загруженных файлов:

| Формат | Библиотека |
|---|---|
| PDF | `pdf-parse` / `pdfjs-dist` |
| DOCX | `mammoth` |
| TXT / MD | нативно |
| (позже) веб | `cheerio` + fetch, аккуратно |

Риск: при извлечении текста нейронка может «додумать» пропущенное. Требование — сохранять ссылку на источник и не выдумывать (см. `04-agents.md`, правила Builder'а).

---

## 9. Эмбеддинги (для семантического поиска)

- Онлайн: OpenAI `text-embedding-3-small` — дёшево, качественно, но требует интернета и API-ключа.
- Локально: `@xenova/transformers` (Transformers.js) — эмбеддинги в Node без внешнего API. Медленнее, но приватно и оффлайн.
- Хранилище векторов: на старте — просто JSON + косинусная близость в памяти (правил не миллионы). Позже — `sqlite-vec` или отдельная векторная БД.

Выбор online/offline — открытый вопрос (`07-open-questions.md`), зависит от того хотим ли полностью локальную работу.
