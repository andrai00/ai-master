# Структура интерфейса

Визуальное устройство сайта. Не дизайн, а структурная раскладка: что где
находится, как связаны экраны, какие компоненты на каких страницах.

Интерфейс строится вокруг **трёх ролей**: неавторизованный, игрок, админ.
У каждой роли — своя доступная навигация и видимые панели.

URL-структура маршрутов:

```
/                         — чат игры (главная)
/chat/personal            — личный чат с мастером
/admin                    — панель администратора (→ /admin/users)
/admin/users              — управление пользователями
/admin/builder            — чат настройки AI мастера (dev-only)
/admin/documents          — документы игры (dev-only)
/admin/logs               — логи размышлений AI (dev-only)
/admin/ai-settings        — настройки подключения AI
```

Каждая страница — отдельный URL-роут (Next.js App Router).
Переходы — через ссылки в сайдбаре, а не через табы.
Табы отменены: усложняли навигацию без выигрыша.

## 1. Каркас приложения (Shell)

Двухколоночная раскладка: сайдбар слева, контент справа.

```
┌──────────┬───────────────────────────────┐
│          │                               │
│  SIDEBAR │                               │
│          │                               │
│  чаты    │      CONTENT AREA             │
│  💬 ●3   │      (Next.js children)       │
│  ✉️ ●1   │                               │
│ ──────── │                               │
│  секции  │                               │
│  │       │                               │
│  персонаж│                               │
│  шпаргал.│                               │
│  общее   │                               │
│  сцена   │                               │
│ ──────── │                               │
│ profile  │          INPUT BAR            │
│          │    (только на страницах чата)  │
└──────────┴───────────────────────────────┘
```

**Реализация:** Ant Design `Layout` с `Sider` (слева), `Content` (центр).
Контент — Next.js `children` (роутинг через App Router).

### 1.1. Левая панель (Sidebar)

Фиксированная, сворачиваемая в ленту 48px. Две логические зоны.

**Шапка сайдбара:** логотип `ai-master` и выпадающий список выбора текущей игры.
Админ видит все свои игры, игрок — только те к которым есть доступ.
Переключение меняет весь контекст: чаты, документы, AI-память.

**Зона 1 — чат-навигация (всегда видна):**
```
💬 Чат игры
✉️ Вопрос мастеру
```
Меню-элементы с иконками. Переключение между общим и личным чатом с мастером.

**Зона 2 — контекстные секции (зависят от игры):**
Секции и их содержимое определяются системой (Builder настраивает).
Пользователь видит не сырую файловую систему, а человекочитаемое меню.

**Игрок:**
```
💬 Чат игры
💬 Вопрос мастеру

📁 Файлы игры (контекстные секции)
```

**Админ (game mode):** то же что игрок + админ-панель (Пользователи, AI настройки).

**Админ (dev mode):** то же + чат настройки AI, документы (там же Экспорт/Импорт Правил и Мозга), логи.
Личный чат скрыт в dev-режиме.

### 1.1а. Маршрутизация сообщений (Chat Routing)

Нейронка сама решает куда отправить ответ — в общий или личный чат. Игрок пишет
в любое поле, агент анализирует и маршрутизирует:

- **Общий чат:** игровые действия, броски, описание сцен — всё что касается всех.
- **Личный чат («Вопрос мастеру»):** правила, создание персонажа, личные проверки,
  скрытые действия — всё что не должно отвлекать других.

Логика: если вопрос игрока не относится к текущей сцене или потенциально портит
погружение другим — нейронка отвечает в личном чате. Например:
- «Какие заклинания у мага 3 уровня?» → личный чат
- «Я атакую гоблина» → общий чат
- «У меня нет персонажа» → личный чат + предложение создать

**Шеринг из личного в общий:** у каждого сообщения в личном чате есть кнопка
«Поделиться». При нажатии в общем чате появляется компактная строка-событие:
«Гаррет поделился сообщением из личного чата» — как системные сообщения в Telegram.
Строка кликабельна: раскрывает затемнённый блок с сообщениями диалога.

Группировка: если один игрок делится несколькими сообщениями подряд (без
других событий между ними), они группируются под одной строкой-событием.
Если между shared-сообщениями появляется обычное сообщение — создаётся новое
событие.

**Раскладка сообщений:**
- Мастер (AI) — слева, аватар + имя роли
- Игрок — справа, аватар + имя
- Одинаково в обоих чатах
- Сообщения из личного чата в общем — с пометкой «из личного чата» и затемнённые

### 1.2. Навигация и роутинг

Табы отменены. Каждый тип контента — отдельная страница со своим URL.
Next.js App Router, каждая страница — `page.tsx` в своей директории.

Навигация происходит через сайдбар (клик по элементу = переход по ссылке).
Шапка сайдбара всегда показывает название приложения и сессии. На мобилке —
только текущая страница, без панели роутинга.

URL-структура (предварительная):
```
/                         — чат игры (главная)
/chat/private             — личный чат с мастером
/characters/[id]          — лист персонажа (deep-link; основной просмотр — модалка предпросмотра)
/rules/[path]             — просмотр правила
/admin                    — панель администратора
/admin/users              — управление пользователями
```

## Компоненты Ant Design — привязка к структуре
- Активные эффекты (список)
- (Для админа) что сейчас в контексте агента: загруженные скилы, файлы.

## 2. Страницы и экраны

### 2.1. Вход (`/`)

Минимальный экран: форма логина и регистрации. Без сайдбара, без вкладок.

Центр: карточка с `Tabs` (Вход / Регистрация), внутри — форма из двух
полей (логин, пароль) + кнопка.

```
┌────────────────────────────┐
│      ┌──────────────┐      │
│      │ Вход / Регист │      │
│      │              │      │
│      │ [логин    ]  │      │
│      │ [пароль   ]  │      │
│      │ [  Войти  ]  │      │
│      └──────────────┘      │
│                            │
│  ai-master: ИИ-мастер      │
│  для ролевых игр           │
└────────────────────────────┘
```

После входа — админ попадает в `/admin`, игрок — в `/sessions`.

### 2.3. Builder — настройка мастера (`/admin/masters/[id]`)

Админ общается с Builder-агентом. Интерфейс — чат, очень похожий на Game
Master но контекст другой.

```
┌──────────┬──────────────────────────────────┬───────────────┐
│ Дерево   │  [Чат с Builder] [rules/*] ...   │               │
│ мастера  │                                  │               │
│          │  Builder: Загрузи rules.pdf —    │               │
│ rules/   │  оглавление найдено. Создать     │               │
│   _index │  структуру глоссария?            │               │
│   races/ │                                  │               │
│   class/ │  Админ: да, создавай             │               │
│   ...    │                                  │               │
│          │  Builder: Готово. 24 термина,    │               │
│          │  6 рас, 4 класса. Открываю       │               │
│          │  правила → races/elf.md          │               │
│          │                                  │               │
│          │  ┌────────────────────────────┐  │               │
│          │  │ [Загрузить файл]           │  │               │
│          │  └────────────────────────────┘  │               │
│          │                                  │               │
│ ──────── │  ─────────────────────────────   │               │
│          │  [сообщение...            ▶]     │               │
└──────────┴──────────────────────────────────┴───────────────┘
```

Особенности Builder-чата:
- Ответы агента могут быть длинными — рендер Markdown с форматированием.
- Кнопка загрузки файлов (`Upload` из Ant) всегда в поле ввода.
- Агент задаёт вопросы с вариантами → рендерятся как Ant `Radio.Group`
  внутри сообщения.
- Агент может открыть файл правил → появляется новая вкладка с правилом.

### 2.4. Игровая сессия (`/sessions/[id]`)

Центральный экран. Игрок и админ видят его по-разному.

#### Вид игрока — вкладка «Общий чат»

```
┌──────────┬──────────────────────────────────┬───────────────┐
│ Мой      │  [Общий чат] [Гаррет] [Карта]   │  Сцена        │

│          │  🧙 Мастер: Вы входите в         │  Таверна      │

│  Инвент. │  Три гоблина за столом.         │  у стойки"    │
│          │                                  │               │
│ Общее    │  ⚔️ Эльф (Элен): Я подхожу к   │  Эффекты:     │
│  Карта   │  стойке и заказываю эль.        │  нет          │
│  Корабль │                                  │               │
│          │  🧙 Мастер: Бармен кивает.      │               │
│          │  Гоблины косятся на вас.         │               │
│ ──────── │                                  │               │
│ Элен     │  ⚔️ Эльф (Элен): Гаррет,        │               │
│ (онлайн) │  обойди их сзади.                │               │
│          │                                  │               │
│          │  🧙 Мастер: Гаррет, сделай       │               │
│          │  проверку скрытности.            │               │
│          │  ┌──────────────────────┐       │               │
│          │  │ 🎲 Скрытность D20+5  │       │               │
│          │  └──────────────────────┘       │               │
│          │                                  │               │
│          │  ─────────────────────────────   │               │
│          │  [сообщение...            ▶]     │               │

Детали:
- Сообщения — Ant `List` с кастомным рендером. Аватарка + имя + текст.
- Кнопки бросков — Ant `Button` с иконкой, встроены в сообщение агента.
- Подсветка `/команд` — цветом или тегом.
- Поле ввода — Ant `Input.TextArea` с автосаджестом `/команд` (Ant `AutoComplete`).
- Игрок переключается на личную вкладку с мастером — отдельный чат (не виден другим).

│          │  **КД:** 15                      │               │
│ Общее    │                                  │               │
│  Карта   │  ## Характеристики               │               │
│  Корабль │  | СИЛ | ЛОВ | ТЕЛ | ИНТ | МУД |│               │
│          │  |-----|-----|-----|-----|-----| │               │
│ ──────── │  | 8   | 18  | 14  | 12  | 10  | │               │
│          │                                  │               │
│          │  ## Инвентарь                    │               │
│          │                                  │               │
│          │  🗡️ Короткий меч  1d6 piercing ▸│               │
│          │  🛡️ Кожаный доспех  КД 11      ▸│               │
│          │  🧪 Зелье лечения  (3 шт)       ▸│               │

│          │                                  │               │

Детали:
- **Формулы скрыты** — игрок видит результат, не вычисления; формула доступна по наведению (свёрнутая панель «Формулы · N», у инлайн-значения — поповер). Ошибка формулы — бейдж `err`.

- Прогресс-бар HP — Ant `Progress`.
- Таблица характеристик — Ant `Table` (или Markdown-таблица с кастомным
  рендером).

#### Вид админа в сессии — то же + доп. вкладки

У админа в той же сессии есть:
- Все личные чаты со всеми игроками (несколько вкладок).
- Вкладка «Логи» — `sessions/<id>/logs/chat.md` и `events.md`.
- Вкладка «Состояние» — `sessions/<id>/state/scene.md`.
- Ручное управление: добавить эффект, изменить сцену, подсказать игроку.

Админ видит **всех игроков** в левом дереве.

## 3. Типы страниц (роуты)

Каждый тип контента — отдельная страница Next.js:

| Страница | URL | Содержимое |
|---|---|---|
| Чат игры | `/` | Чат сессии (главная) |
| Личный чат | `/chat/private` | Чат игрока с мастером |
| Лист персонажа | Модалка предпросмотра (из сайдбара / wiki-ссылок) | Рендер composite-документа; `/characters/[id]` — deep-link fallback |
| Правило | `/rules/[path]` | Рендер `.md` файла глоссария |
| Админ-панель | `/admin` | Список мастеров и сессий |
| Пользователи | `/admin/users` | Управление аккаунтами |

## 4. Компоненты Ant Design — привязка к структуре

| Компонент Ant | Где |
|---|---|
| `Layout` + `Layout.Sider` + `Layout.Content` | Каркас (левый сайдбар + контент) |
| `Tree` | Файловое дерево в левом сайдбаре |
| `Input.TextArea` + `Button` | Поле ввода сообщений в чатах |
| `List` + `List.Item` | Сообщения в чате |
| `Button` (+ `Tooltip`) | Кнопки бросков в сообщениях |
| `Progress` | Полоса HP в листе персонажа |
| `Table` | Таблицы характеристик, инвентаря |
| `Descriptions` | Детализация предмета/эффекта |
| `Card` | Карточки мастеров на дашборде админа |
| `Upload` + `Dragger` | Загрузка файлов правил (Builder) |
| `Modal` | Диалоги подтверждения, настройки |
| `Dropdown` + `Menu` | Контекстное меню профиля |
| `Badge` | Счётчики непрочитанных в сайдбаре |
| `Switch` | Переключатель темы |
| `Select` | Выбор языка |
| `Avatar` | Аватары пользователей и мастера |
| `notification` | Тосты: успех, ошибка |
| `Spin` | Загрузка |
| `Empty` | Пустое состояние |

## 5. Сквозной сценарий: D&D 5e (иллюстрация)

### Админ настраивает мастера

1. Входит → `/admin` → жмёт «Создать мастера».
2. Даёт название: «D&D 5e — Забытые Королевства».
3. Открывается Builder-чат. Builder пишет: «Загрузите правила».
4. Админ перетаскивает `phb.pdf` в поле загрузки.
5. Builder: «Оглавление найдено. 3 части, 14 глав. Начать с рас и классов?»
6. Админ: «Да». Builder создаёт структуру в `rules/`.
7. Админ видит как в левом дереве появляются файлы.
8. Builder: «Готово. Есть неясность — эльфы получают +1 или +2 к ловкости?» → ответы-кнопки.
9. Админ выбирает +2.
10. Builder продолжает: заклинания, снаряжение, боевые правила.

### Игрок создаёт персонажа

1. Игрок входит → главная страница `/`.
2. GM в личном чате: «У тебя нет персонажа. Давай создадим?»
3. Игрок: «Давай».
4. GM: «Выбери расу: человек / эльф / дварф / полурослик» → кнопки в чате.
5. Игрок жмёт «полурослик». GM: «Теперь класс: плут / воин / маг / ...»
6. Шаг за шагом — готовый лист. Игрок открывает его кликом в сайдбаре — предпросмотр в модалке.

### Игровой процесс

1. GM в общем чате: «Вы входите в таверну. Три гоблина за столом.»
2. Элен (игрок 2): «Я подхожу к стойке».
3. Гаррет в личке GM'у: «Пытаюсь незаметно пробраться за спину гоблинам».
4. GM (только в личке Гаррету): «Сделай проверку скрытности» → кнопка 🎲 D20+5.
5. Гаррет жмёт кнопку → результат: 18.
6. GM в личке Гаррету: «Ты успешно скрылся в тени за их спинами».
7. GM в личке Элен: «Сделай проверку восприятия» (не объясняя зачем).
8. Элен жмёт кнопку → результат: 7. GM: «Ты не замечаешь ничего необычного».

```

    admin/                — админ-панель
  widgets/
    shell/                — каркас: Layout + сайдбар + контент (children)

## 7. Адаптивность и мобильная версия

### 7.1. Десктоп (>= 768px)

Текущая реализация: сайдбар фиксированный (сворачивается в ленту 48px),
таб-бар с вкладками, контент во всю оставшуюся высоту.

### 7.2. Мобильная версия (< 768px)

- **Сайдбар** — выезжает как drawer-шторка поверх контента, закрывается
  по клику на затемнение или по кнопке.
- **Таб-бар скрыт полностью** — на мобильном экране вкладки не
  показываются. Пользователь видит только текущий контент.
- **Кнопка меню** — в левом верхнем углу контента, открывает сайдбар.
- **Навигация по табам** (будущая реализация):
  - Свайп влево/вправо по контенту переключает вкладки.
  - Или выпадающий список вкладок в верхней части экрана.
  - Или нижняя панель с иконками табов (как в мобильных приложениях).
  - Точный механизм будет выбран на этапе реализации мобильной версии.
- **Сайдбар на мобилке** — может быть заменён на нижнюю навигационную
  панель (bottom sheet) для быстрого доступа к дереву файлов и профилю.

### 7.3. Общие правила адаптива

- `max-width: 760px` на контенте (чат и MD) — единая ширина чтения.
- CSS-переменные для цветов и отступов — одна точка правки.
- Компоненты не зависят от размера экрана внутри себя — адаптив
  управляется на уровне Shell.

## 8. Реализовано и готово к реальному использованию

Следующие UI-компоненты и фичи полностью работают, протестированы
и ждут подключения к реальным данным:

**Чат-панель (`ChatPanel`):**
- Сообщения с аватарами (Builder `CodeOutlined`, мастер `RobotOutlined`, игрок `UserOutlined`)
- Мастер/Builder — слева, игрок/админ — справа
- Кнопки «Копировать», «Удалить» (с подтверждением), «Поделиться» (скрывается в builder-чате)
- Индикатор набора (три анимированные точки)
- Enter = отправить, Shift+Enter = новая строка
- Контролируемое поле ввода (useState, не ref)
- Шапка с заголовком и кнопками действий (история, очистка)
- Баннер блокировки в dev-режиме

**Сайдбар:**
- GameSelector — название игры как заголовок (кликабельно для админа)
- ChatNav — Чат игры (`/`), Вопрос мастеру (`/chat/personal`)
- AdminSection — Пользователи, AI настройки, режим, Builder, документы (Экспорт/Импорт), логи
- Подсветка активной страницы (usePathname)
- Переключатель режима (development/game) с акцентной левой полосой
- Профиль с аватаром (data-uri, useUserAvatar), контекстное меню
- Сворачивание в ленту 48px

**Builder Chat (`/admin/builder`):**
- Ping-pong с оптимистичными сообщениями
- Запуск агента — только кнопкой «Запросить ответ» (не автоматически после отправки). Кнопка подхватывает `fileIds` из последнего сообщения
- Во время обработки: отправка сообщений и броски блокируются серверно (`chat.processingBlocked` + уведомление)
- Автосаммари каждые 20 сообщений (один Document, кумулятивно)
- Очистка чата с подтверждением
- История в модалке с пагинацией (30 на страницу, последние сверху)

**Аватары:**
- Хранение base64 в `User.avatar`
- Единый хук `useUserAvatar(userId)` — кэш React Query, инвалидация при upload/delete
- Загрузка/удаление через API Routes (upload-avatar, delete-avatar)

**Страницы:**
- `/admin/builder` — чат настройки AI
- `/admin/users` — управление пользователями
- `/admin/documents` — просмотр документов по категориям (табы)
- `/admin/logs` — лента размышлений AI (Timeline)
- `/admin/ai-settings` — настройки провайдера, API ключ, модель
- `/chat/personal` — личный чат (заглушка)

**Тема и i18n:**
- Переключение тёмная/светлая (localStorage)
- Переключение языка (русский/английский)
- Все строки в JSON-локалях с trailing comma
