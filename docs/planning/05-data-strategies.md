# Стратегии работы с данными

> **Обновлено:** хранение переведено на Prisma + SQLite (см. `03-architecture.md`). Все данные — документы в БД с категориями (`glossary`, `brain`, `game_hidden`, `game_visible`). Поиск работает по колонкам и контенту. Принципы progressive disclosure и индексного поиска без изменений.

## Проблема

Правила игры — сотни страниц. Грузить всё в контекст LLM на каждый запрос: дорого, медленно, нейронка путается. Агент должен **искать точечно** — нужный кусок именно когда потребовался.

---

## Два режима поиска

### Полнотекстовый (`search_content`)

Быстрый grep по файлам. Инструмент: `search_content(query, path?)`.

**Когда:**
- Конкретный термин («что такое тёмное зрение?»)
- Поиск по ключевому слову («скрытность», «яд», «падение»)

**Ограничения:** не понимает синонимы, не понимает контекст.

### Семантический (`semantic_search`)

Поиск по смыслу через эмбеддинги. Инструмент: `semantic_search(query)`.

**Когда:**
- Игрок описал действие не зная термина («хочу тихо пробраться»)
- Сложный запрос («как лечить яды разными способами?»)
- Правила размазаны по разным секциям

**Реализация:**
- Builder при создании глоссария строит индекс: `rules/.index/embeddings.json` + `mapping.json`
- Game Master вызывает `semantic_search` → платформа эмбеддит запрос → ищет ближайшие → возвращает top-N кусков с путями к файлам

Выбор online (OpenAI) vs offline (Transformers.js) эмбеддингов — открытый вопрос (`07-open-questions.md`).

## Progressive disclosure (послойное раскрытие)

Агент не читает весь файл сразу. Идёт слоями от лёгкого к тяжёлому:

### Слой 1: Оглавление (`_index` / README)

Всегда в контексте. Маленький документ — карта всего что есть во всех категориях. AI сам создаёт и поддерживает его. Это не только оглавление глоссария, а **навигационный README** по всем документам мастера:

```md
# Структура мастера

## Глоссарий (правила игры)
- Расы → `race-abc123`
- Классы → `class-def456`
- Бой → `combat-ghi789`

## Мозг (инструкции ИИ)
- Порядок создания персонажа → `brain-char-creation`
- Алгоритм боя → `brain-combat-flow`
- Маршрутизация ответов → `brain-routing`

## Скрытые заметки
- Текущая сцена: планы → `hidden-scene-42`
- Саммари сессии → `hidden-summary-s1`
- Секреты персонажей → `hidden-secrets`

## Видимые документы (игроки)
- Лист: Арагорн → `visible-char-a1` (player: user-xyz)
- Лист: Гэндальф → `visible-char-g1` (player: user-abc)
- Общая информация о мире → `visible-world`
```

**Зачем README:**
- AI не ищет рандомно — сначала смотрит README, потом идёт в нужный документ
- README обновляется при добавлении/удалении документов (AI сам или платформа)
- README — первый документ который читает Game Master при старте
- Для Builder'а — отдельный README только по glossary/brain

### Слой 2: Front-matter (TL;DR)

Каждый файл правил начинается с front-matter:

```yaml
---
title: "Эльф"
summary: "Лесная раса. +2 ловк, тёмное зрение, владение луками."
keywords: [эльф, раса, ловкость, зрение, лук]
---
```

Агент читает **только front-matter** релевантных файлов чтобы понять какой открывать.

### Слой 3: Полное содержание

Когда агент определил что файл нужен — читает целиком.

### Слой 4: Связанные файлы

Внутри файла ссылки: `[[mechanics/dark-vision]]`. Агент идёт по ссылкам если нужно.

## Стратегия для Builder'а (изучение правил)

1. **Первый проход — оглавление.** Парсит PDF → ищет/составляет оглавление → показывает админу
2. **Приоритеты.** Что важно немедленно (создание персонажа), что для игры (механики), что отложить (лор)
3. **Посекционный разбор.** Каждую важную секцию: читает → выделяет суть → сохраняет как `glossary`-документ с TL;DR → добавляет термины
4. **Вопросы админу.** Противоречия, пробелы, варианты правил — вопрос с вариантами + свой ответ
5. **Составление карты.** Создаёт README-документ (`brain`, type=`_index`) — полную карту глоссария и мозга. Game Master читает его первым всегда
6. **Создание мозга.** На основе глоссария пишет `brain`-документы: порядок создания персонажа, алгоритмы обработки ситуаций, правила маршрутизации

## Что в контексте агентов

### Game Master — Game Chat

- System prompt (правила платформы, включая правила безопасности ссылок)
- README-индекс (`brain` с type=`_index`) — карта ВСЕХ категорий (не только глоссария)
- `game_visible` лист персонажа игрока с которым общается
- Саммари старых сообщений (`game_hidden` с type=summary)
- Последние 10 сообщений чата
- Если был переход dev→game: migration summary (`brain` с type=migration_summary)

### Game Master — Personal Chat

- То же что Game Chat + порядок создания персонажа из `brain`
- `game_visible` лист только этого игрока

### Builder — Builder Chat

- System prompt (ты Builder, твоя задача)
- README-индекс `brain` и `glossary` (карта того что уже построено)
- Саммари старых сообщений builder-чата
- Заметки-память (`game_hidden` / `brain`)
- Последние 10 сообщений builder-чата

## Что загружается ПО ЗАПРОСУ

- Конкретный документ `glossary` или `brain` (когда игрок спросил или агент понял что нужно)
- `game_visible` листы других персонажей (только если общая сцена или скрытое действие)
- `game_hidden` заметки мастера (если нужно вспомнить контекст)
- Связанные документы по перекрёстным ссылкам `[[doc-id]]`

## Алгоритм поиска в глоссарии (Game Master)

```
Игрок: "хочу переплыть реку"
    │
    ▼
Агент: _index.md → "передвижение: mechanics/movement.md"
    │
    ▼
Читает TL;DR mechanics/movement.md:
  "Плавание: проверка Атлетики СЛ 15"
    │
    ▼
Достаточно → отвечает игроку
```

Если TL;DR недостаточно → полный файл.
Если полного файла недостаточно → `semantic_search("плавание в броне")` → связанное правило.

## Контекстное окно: стратегии кэширования

### Скользящее окно

Последние N сообщений в контексте всегда. Остальное — в логах на диске. Если нужно вспомнить — `search_content` по логам.

### Авто-саммари

Каждые ~K сообщений агент пишет саммари "что произошло" в `sessions/<id>/state/summary.md`. При следующем запросе свежий саммари загружается в контекст как замена сырой истории.

### Ручной recall

Игрок: "а что тот NPC говорил про подземелье?" → агент ищет по логам (полнотекстовый или семантический) → находит → отвечает.

## Инструменты поиска (сводка)

| Инструмент | Назначение |
|---|---|
| `search_content(query, category?)` | Полнотекстовый grep по контенту документов |
| `semantic_search(query)` | Поиск по смыслу через эмбеддинги |
| `read_document(id)` | Полный документ (включая summary) |
| `read_summary(id)` | Только summary документа (TL;DR) |
| `get_index()` | README-индекс (`brain`, type=`_index`) |
| `search_messages(query)` | Поиск по истории чатов |
| `write_document(title, content, category, ...)` | Создать/обновить документ |
| `write_note(title, content)` | Создать заметку-память в `game_hidden` |

## Индексация (делает Builder, пользуется Game Master)

Builder создаёт два вида индексов для быстрого поиска:

### 1. README-индекс (навигационный документ)

Документ `brain` с type=`_index`. Читается агентом первым при любом запросе. Содержит карту всех документов с краткими описаниями. Обновляется при добавлении/удалении документов.

### 2. Семантический индекс

Для поиска по смыслу через эмбеддинги. Хранится как `brain`-документы с type=`embedding_index`:

```
brain-документ type=embedding_index:
  content = JSON {
    embeddings: [...],     ← векторные представления секций правил
    mapping: {...}         ← {embedding_id → document_id + заголовок секции}
  }
```

`semantic_search(query)`:
1. Эмбеддит запрос
2. Ищет ближайшие в индексе
3. Через mapping находит document_id
4. Возвращает top-N релевантных документов с заголовками
