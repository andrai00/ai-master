## Ant Design — подключение

```bash
pnpm add antd @ant-design/icons
```

```ts
import { Button, Input, Modal, notification, Table, Tree, Tabs, Layout, Menu, Breadcrumb } from "antd";
```

Глобальный импорт — Ant Design поддерживает tree-shaking из коробки (с v5).

### Тема и провайдер

`ConfigProvider` из Ant Design оборачивает всё приложение в `src/app-layer/index.tsx`:

```tsx
"use client";

import { ConfigProvider, theme, App } from "antd";
import ruRU from "antd/locale/ru_RU";
import { QueryClientProvider } from "@tanstack/react-query";
import { Suspense, FC, ReactNode } from "react";
import { queryClient } from "./providers/query-provider";

const Providers: FC<{ children: ReactNode }> = ({ children }) => (
  <QueryClientProvider client={queryClient}>
    <ConfigProvider
      locale={ruRU}
      theme={{
        algorithm: theme.darkAlgorithm,
        token: {
          colorPrimary: "#1677ff",
          borderRadius: 6,
        },
      }}
    >
      <App>
        <Suspense fallback={<div>Loading...</div>}>
          {children}
        </Suspense>
      </App>
    </ConfigProvider>
  </QueryClientProvider>
);

export default Providers;
```

- `App` — обязательная обёртка для `notification`, `message`, `modal` (статические методы в Ant Design v5).
- `ruRU` — русская локаль.

### CSS

Ant Design v5 использует CSS-in-JS (cssinjs), конфликтов с CSS Modules нет. Глобальные токены темы — через `ConfigProvider`, дополнительные стили — CSS Modules рядом с компонентом.

## Общие принципы

**Notion/Obsidian aesthetic**: минимализм, тёмная тема, чёткая иерархия, без украшений. Никаких градиентов, теней, скруглений больше 8px.

**Цвета**: только CSS-переменные. Основные: `var(--text-primary)`, `var(--text-dim)`, `var(--text-muted)`, `var(--border)`, `var(--bg-hover)`, `var(--bg-active)`. Никаких `#333`, `#d4d4d4`, `#1a1a1a`.

**Иконки**: только `@ant-design/icons`. Без эмодзи. Иконки-онли кнопки всегда с `<Tooltip>`.

**Адаптивность**: каждый компонент должен работать на `< 768px`. Брейкпоинт в CSS Modules: `@media (max-width: 767px)`.

**Шрифты**: 14px body, 12px secondary, 10px labels, 16px page titles. Font-weight: 400 normal, 500 medium, 600 headings.

## Структура интерфейса

Интерфейс строится вокруг **трёх ролей**: неавторизованный, игрок, админ. Каждая страница — отдельный URL-роут (Next.js App Router). Переходы — через ссылки в сайдбаре, а не через табы. Табы отменены.

URL-структура маршрутов:

```
/                         — чат игры (главная)
/chat/personal            — личный чат с мастером
/characters/[id]          — лист персонажа (deep-link; основной просмотр — модалка предпросмотра)
/admin                    — панель администратора (→ /admin/users)
/admin/users              — управление пользователями
/admin/builder            — чат настройки AI мастера (dev-only)
/admin/documents          — документы игры (dev-only)
/admin/logs               — логи размышлений AI (dev-only)
/admin/ai-settings        — настройки подключения AI
```

### Каркас приложения (Shell)

Двухколоночная раскладка: сайдбар слева, контент справа. Реализация: Ant Design `Layout` с `Sider` (слева), `Content` (центр). Контент — Next.js `children` (роутинг через App Router).

#### Левая панель (Sidebar)

Фиксированная, сворачиваемая в ленту 48px. Две логические зоны.

**Шапка сайдбара:** логотип `ai-master` и выпадающий список выбора текущей игры (GameSelector). Админ видит все свои игры, игрок — только те к которым есть доступ. Переключение меняет весь контекст: чаты, документы, AI-память.

**Зона 1 — чат-навигация (всегда видна):**
```
Чат игры
Вопрос мастеру
```

**Зона 2 — контекстные секции (зависят от игры):** определяются системой (Builder настраивает). Пользователь видит не сырую файловую систему, а человекочитаемое меню.

**Игрок:** чат игры + вопрос мастеру + файлы игры (контекстные секции).

**Админ (game mode):** то же что игрок + админ-панель (Пользователи, AI настройки).

**Админ (dev mode):** то же + чат настройки AI, документы (там же Экспорт/Импорт Правил и Мозга), логи. Личный чат скрыт в dev-режиме.

##### AdminSection — порядок элементов

**Game mode:**
```

Пользователи
AI настройки

```

**Development mode:**

```
Документы

```

##### Активная страница

Все навигационные элементы подсвечивают активную страницу:
- `usePathname()` + `startsWith(route)`
- Стиль: `background: var(--bg-active); color: var(--text-primary);`
- Каждый новый пункт меню — сразу с этим

##### Кнопка режима

- Обычный `<button>`, НЕ Ant Design Button
- Стиль: с левым акцентом `border-left: 3px solid var(--text-dim)`
- На всю ширину, никакого `danger` или цветного фона — нейтральный

### Маршрутизация сообщений (Chat Routing)

Нейронка сама решает куда отправить ответ — в общий или личный чат. Игрок пишет в любое поле, агент анализирует и маршрутизирует:

- **Общий чат:** игровые действия, броски, описание сцен — всё что касается всех.
- **Личный чат («Вопрос мастеру»):** правила, создание персонажа, личные проверки, скрытые действия — всё что не должно отвлекать других.

**Шеринг из личного в общий:** у каждого сообщения в личном чате есть кнопка «Поделиться». В общем чате появляется компактная строка-событие. Строка кликабельна: раскрывает затемнённый блок. Группировка: если один игрок делится несколькими сообщениями подряд — они группируются под одной строкой.

**Раскладка сообщений:** Мастер (AI) — слева, аватар + имя роли; Игрок — справа, аватар + имя. Одинаково в обоих чатах. Сообщения из личного чата в общем — с пометкой «из личного чата» и затемнённые.

## Шапки страниц

### Единый компонент `PageHeader`

**Все страницы** используют `<PageHeader title="..." actions={...} />` из `src/shared/ui/page-header.tsx`. Никаких inline-стилей, отдельных `<h2>`, самописных header-дивов.

```
┌──────────────────────────────────────────┐
│ ☰  Page Title              [действия]    │
└──────────────────────────────────────────┘
```

- В мобилке: кнопка `MenuOutlined` слева от заголовка (на одной строке, не отдельным рядом)
- Заголовок: 14px, font-weight 600, без иконок в заголовке
- Действия: `margin-left: auto`
- Разделитель снизу: `border-bottom: 1px solid var(--border)`
- Ширина: `max-width: var(--content-width); margin: 0 auto`
- Мобилка: `padding: 6px 12px; font-size: 13px`
- Кнопка меню через `MobileMenuProvider` (React Context) — Shell оборачивает children

Страницы с ChatPanel рендерят свою шапку с мобильной кнопкой меню через `useMobileMenu()`. Шапка показывается даже без заголовка на мобилке (только кнопка меню).

## Формы и страницы настроек

- Ширина: `440px`, `max-width: 100%` — на мобилке растягивается на весь экран
- Центрирована `margin: 0 auto`
- Поля — простые `<div>` с label сверху, без Ant Design `Card`
- Label: `font-size: 12px; color: var(--text-muted); marginBottom: 4px`
- Отступ между полями: `gap: 14px`
- Кнопка сохранения внизу, на всю ширину
- Шапка: через `PageHeader` компонент

### Select (выпадающие списки)

- Стандартный Ant Design `Select` с `width: "100%"`
- Для больших списков (модели AI): `listHeight={256}` — Ant Design сам виртуализирует
- Не использовать `react-window` — несовместим с текущей версией
- При загрузке опций: `notFoundContent={<Spin size="small" />}`

## Таблицы

- `size="small"`
- `pagination={{ pageSize: 20, hideOnSinglePage: true }}`
- Вся строка кликабельна: `onRow` с `cursor: pointer`

### Модалка просмотра

- Таблица → клик по строке → `<Modal>` с контентом
- Контент: Markdown через `MdViewer` (react-markdown), либо `white-space: pre-wrap` для plain text

### Таблицы в Markdown-контенте

- GFM-таблица: шапка + separator (`|---|---|`) + строки — рендерится в `<table>` через remark-gfm
- `cleanContent` в `md-viewer.tsx` чистит два бага импортированного контента:
  1. blockquote-загрязнение `> | col |` → снимает `> `
  2. separator ПЕРЕД шапкой (поломанный порядок) → меняет местами ТОЛЬКО когда separator начинает блок (после пустой строки/начала документа)
- ⚠️ НЕ чинить separator «на глаз» regex-ом по каждой строке: `^` с флагом `m` матчит начало любой строки и ломает корректные таблицы (шапка выпадает из таблицы). Флаг `m` у перестановки — ЗАПРЕЩЁН

## Чат

### Шапка

```
│ ☰  Настройка AI мастера      🗑  📋 │
```

- Мобильная кнопка меню слева (через `useMobileMenu()`)
- Заголовок: `font-size: 13px; font-weight: 600`
- Кнопки действий справа: `type="text" size="small"`
- Ширина шапки: `max-width: var(--content-width); margin: 0 auto`
- Разделитель снизу: `border-bottom: 1px solid var(--border)`
- На мобилке без заголовка — только кнопка меню (пустая шапка)

### Сообщения

- Админ: справа, фон `var(--bg-hover)`, border-radius: 12px (правый нижний 4px)
- Мастер/Builder: слева, фон `var(--bg-bubble)`, border: 1px solid var(--border)
- Аватары: 32px, иконка зависит от роли (UserOutlined, RobotOutlined, CodeOutlined)
- Текст: `white-space: pre-wrap; word-break: break-word`
- Кнопки действий (copy/delete) на бабле, opacity 0 → 1 при hover строки

### Поле ввода

- `Input.TextArea` + кнопка Send рядом
- Контролируемое состояние (`value + onChange`), НЕ ref (Ant Design TextArea ref не работает)
- Enter = отправить, Shift+Enter = новая строка
- Блокируется при отправке (`disabled={sending}`)

### Индикатор набора (typing)

- Три анимированные точки в бабле мастера
- CSS анимация `dotPulse`: opacity + scale, задержка 0.2s между точками

### Переключатель режимов (Мозг/Память) на мобилке

- В десктопе: рядом с полем ввода (в `inputInner` flex-ряду)
- На мобилке: `flex-wrap: wrap` + `width: 100%` → на отдельной строке над инпутом

### Прогресс-бар файлов

- Компактная строка над инпутом: `📁 2/3 │ 📄 15/32 [⚙] [▶]`
- Все элементы по правому краю (`justify-content: flex-end`)
- `⚙` (SettingOutlined) → tooltip «Детали файлов» → модалка с per-file breakdown
- `▶` (CaretRightOutlined) → tooltip «Продолжить изучать» → продолжение обработки
- При активной обработке: `▶` → `■` (StopOutlined), удаление файлов заблокировано
- Все файлы обработаны → кнопка продолжения скрыта
- Модалка: per-file прогресс-бары, статусы (Готово/Читается/Ожидает), удаление
- Ширина прогресс-бара: `max-width: var(--content-width)`

### История чата

- Кнопка `HistoryOutlined` в шапке
- Модалка с `<Table>` — два столбца: роль + сообщение
- В столбце сообщения: прикреплённые файлы (📎 + имена) над текстом — как в чате
- Пагинация 30 записей на страницу
- Без поля ввода — только чтение

### Кнопка «Вниз» (jump to bottom)

- Плавающая круглая кнопка `DownOutlined`, справа-снизу над полем ввода
- Выровнена по правому краю колонки чата (`max-width: var(--content-width)` + `padding: 0 20px`), НЕ по краю экрана
- Показывается только когда пользователь прокрутил вверх от последнего сообщения (>80px) — `position: sticky; bottom: 16px` внутри scroll-контейнера
- Клик → плавный прыжок к последнему сообщению, кнопка скрывается
- Автоскролл при новых сообщениях работает только если пользователь уже у низа — историю чтения не выдёргивает
- Сброс состояния при смене чата: через render-паттерн (сравнение `prevStepsSessionId`), без setState в эффекте

## Модалки (Modal)

- `centered` — всегда по центру экрана
- Ширина: зависит от контента (300-640px)
- Footer: кнопки Cancel (слева) + Primary действие (справа)
- Деструктивные действия — `Popconfirm`, не отдельная модалка

## Уведомления (notification)

- `success` — после сохранения, переключения режима
- `error` — при ошибках, отказе доступа
- НЕ использовать `info` для системных событий (саммари, обновления) — это спам
- Все тексты через `t()`

## Интернационализация (i18n)

- Библиотека: `i18next` + `react-i18next`
- Все статические тексты в `src/shared/config/i18n/locales/{ru,en}.json`
- Ключи по секциям: `common`, `sidebar`, `profile`, `settings`, `auth`, `chat`, etc.
- Хук: `const { t } = useTranslation()` → `t("auth.login")`
- Язык по умолчанию: браузер → английский
- Переключение через Select в модалке настроек
- Динамический контент (имена, названия из БД) — НЕ переводить
- Все `notification.success({ title: ... })`, `Modal title`, `placeholder`, `Tooltip title` — через `t()`

## Адаптивность

Всегда учитывать мобильную версию при создании UI-компонентов:

- Брейкпоинт: 768px (`@media (max-width: 767px)`)
- На мобилке сайдбар — drawer-шторка, таб-бар скрыт, только текущий контент
- Кнопки/инпуты — достаточного размера для тапа (минимум 32px)
- Контент не должен вылезать за пределы экрана на узких ширинах
- Тестировать оба режима в коде — добавлять `@media` блоки в CSS Modules
- `max-width: 760px` на контенте (чат и MD) — единая ширина чтения

## Обязательные UI-практики

### Каждый UI-компонент — сразу с адаптивом
Не откладывать. Колонки таблиц с `responsive`, padding на мобилке, `flexWrap` у хедеров, иконка-онли кнопки на узких экранах.

### Каждая иконка-онли кнопка — с Tooltip
`<Tooltip title="..."><Button icon={...} /></Tooltip>`. Без исключений.

### Деструктивные действия — с подтверждением
`Popconfirm` для удаления, `modal.confirm` из `App.useApp()` для выхода/смены.

### Danger / красный только для удаления
`type="primary" danger` и красный цвет — только для необратимых действий (удаление, сброс). Для выхода из режима, возврата, закрытия — обычные кнопки, не danger.

### modal.confirm — всегда mask: { closable: true }
`modal.confirm` из `App.useApp()` по умолчанию не закрывается по клику на фон. Всегда добавлять `mask: { closable: true }`.

### Режимы с последствиями — кнопка + подтверждение, не Switch
`Switch` — только для мгновенных toggle без последствий (тема, звук). Смена режима, затрагивающая всех пользователей или меняющая поведение системы — только кнопка с явным текстом (`Button` + текст действия) + `modal.confirm` с объяснением что произойдёт.

### Таблицы — всегда pagination
Даже если данных мало: `pagination={{ pageSize: 10, hideOnSinglePage: true }}`. Не `pagination={false}`.

### Формы
- `input + кнопка` рядом — высота кнопки = `controlHeight` из темы (30px), `align-items: center`, инпут без фиксированной высоты
- `Input.TextArea` — только контролируемое состояние (`useState`)

## Что НЕ делать

- ❌ Ant Design `Card` для группировки полей — простые `<div>`
- ❌ `react-window` — несовместим с текущим стеком
- ❌ `danger` (красный) для не-деструктивных действий (возврат из режима)
- ❌ `Switch` для режимов с последствиями — только `<button>` с подтверждением
- ❌ `Input.TextArea` ref — использовать контролируемое состояние
- ❌ Синие ссылки в таблицах — вся строка кликабельна через `onRow`
- ❌ Эмодзи в интерфейсе
- ❌ Хардкод ширины для адаптивных элементов — только `max-width` или фиксированная для форм
- ❌ Inline-стили для заголовков страниц — только `<PageHeader>`
- ❌ Отдельный ряд для мобильной кнопки меню — кнопка внутри шапки на одной строке
- ❌ Дублирование навигационных пунктов в разных секциях сайдбара
- ❌ antd Tabs overflow-кнопка «...» на мобилке — нативный скролл
