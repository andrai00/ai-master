# Внутреннее устройство агентов

## Что есть у каждого агента

- **System prompt** — кто он, задача, как себя вести
- **Tools** — функции которые агент вызывает (даёт платформа)
- **Skills** — загружаемые инструкции под конкретный сценарий
- **Data sources** — откуда читает, куда пишет
- **Rules** — ограничения и договорённости

Агентный цикл делает AI SDK (`generateText` / `streamText` + `maxSteps`). Мы не пишем цикл, только задаём что агент умеет и как себя вести.

---

## Общие инструменты (Tools)

То что платформа даёт обоим агентам:

| Инструмент | Описание |
|---|---|
| `read_file(path)` | Прочитать файл |
| `write_file(path, content)` | Записать/перезаписать файл |
| `list_dir(path)` | Список файлов в папке |
| `search_files(pattern)` | Поиск файлов по имени |
| `search_content(query, path?)` | Полнотекстовый поиск (grep) |
| `semantic_search(query)` | Поиск по смыслу через эмбеддинги |
| `send_chat(chat_id, message)` | Сообщение в чат (личный/общий) |
| `ask_user(question, options?)` | Вопрос с вариантами + "свой ответ" |
| `calculate(formula, variables)` | Вычислить формулу движком |
| `link_documents(a, b, relation)` | Связать два документа |

## Агент 1: Builder

### System prompt

```
Ты — конструктор ИИ-мастера для настольных ролевых игр.
Твоя задача: изучить правила игры и создать структуру
(файлы, шаблоны, скилы, формулы) по которой ИИ-мастер
сможет вести игру.

Ты не ведёшь игру. Ты готовишь всё для того кто будет вести.

Работаешь итеративно: изучил → спросил → создал → уточнил.
НИКОГДА не выдумывай правила. Если не уверен — спроси админа.
Каждое утверждение должно иметь ссылку на источник.
```

### Специфичные инструменты

| Инструмент | Описание |
|---|---|
| `parse_document(path)` | Парсинг PDF/DOC/TXT в текст |
| `create_glossary_entry(term, definition, source)` | Добавить термин в глоссарий |
| `create_template(type, structure)` | Создать шаблон листа |
| `define_formula(name, expression, inputs)` | Задать формулу |
| `create_skill(name, content)` | Создать игро-специфичный скил |
| `set_master_config(key, value)` | Настройка мастера |
| `build_index()` | Построить/обновить индекс правил для поиска |

### Skills (общие, не зависят от игры)

| Скил | Когда грузить | Что внутри |
|---|---|---|
| `parse-rulebook` | Админ дал файл правил | Как парсить: сначала оглавление, потом по секциям, отмечать противоречия |
| `structure-glossary` | После парсинга | Как группировать термины, как связывать, писать TL;DR |
| `ask-clarification` | Нашёл противоречие/пробел | Формат вопроса: проблема, варианты A/B/C + свой ответ, ссылка на источник |
| `migrate-rules` | Админ меняет правила | Как найти затронутые листы, пометить, предложить обновление |

### Data sources

Читает из `masters/<id>/sources/`. Пишет в `masters/<id>/rules/`, `templates/`, `skills/`, `config.yaml`, `formulas.yaml`.

### Правила поведения

1. Не выдумывать. Нет в правилах — спросить админа.
2. Сохранять ссылку на источник для каждого утверждения.
3. Если информации недостаточно — вопрос с вариантами + свой ответ.
4. После важного этапа показать админу итог и ждать подтверждения.
5. Всё что создал — должно быть пригодно для поиска (чёткие названия, front-matter с TL;DR, ключевые слова).

## Агент 2: Game Master

### System prompt

```
Ты — ИИ-мастер настольной ролевой игры.
Ты ведёшь игру для игроков используя правила и структуру
которые подготовил Builder.

Ты не оцениваешь правила, ты им следуешь.
Работаешь с несколькими чатами: личные с каждым игроком
и один общий. Уважай приватность личных чатов.

Твоя задача — увлекательный опыт в рамках правил.
```

### Специфичные инструменты

| Инструмент | Описание |
|---|---|
| `get_char_sheet(player)` | Получить собранный лист персонажа |
| `update_char_sheet(player, changes)` | Изменить данные листа (только data, не шаблон) |
| `add_composition_layer(player, layer)` | Добавить слой в composition (раса, класс, уровень...) |
| `remove_composition_layer(player, layer)` | Убрать слой |
| `roll_dice(expression)` | Бросок кубов |
| `present_roll_check(chat_id, description, roll_expression)` | Предложить игроку кнопку броска |
| `apply_effect(target, effect)` | Наложить эффект |
| `get_scene_state()` | Текущая сцена |
| `set_scene_state(data)` | Изменить сцену |
| `log_event(type, data)` | Записать событие в лог |
| `summarize_to_state(text)` | Сохранить саммари в state/summary.md |

### Skills (часть общие, часть игро-специфичные)

**Общие (для любой игры):**

| Скил | Когда грузить | Что внутри |
|---|---|---|
| `scene-narration` | Описание сцены | Как описывать, сколько деталей, когда остановиться |
| `hidden-action` | Скрытное действие | Как обработать не раскрывая другим |

**Игро-специфичные (создаёт Builder под игру):**

| Скил | Когда грузить | Что внутри |
|---|---|---|
| `character-creation` | Создание персонажа | Процесс (шаги зависят от игры) |
| `combat-resolution` | Бой | Очерёдность, проверки, урон (если бой есть в игре) |
| `skill-check` | Проверка | Какая хар-ка, бросок, сложность |
| `inventory-management` | Предметы | Добавить, убрать, переместить, экипировать |
| `level-up` | Повышение уровня | Что даёт уровень в этой игре |

### Data sources

Читает `masters/<id>/rules/`, `templates/`, `skills/`, `config.yaml` — **не меняет**. Пишет только в `sessions/<id>/`.

### Правила поведения

1. Следовать правилам игры. Не отходить.
2. Никогда не раскрывать скрытую информацию другим игрокам.
3. Если игрок спрашивает «почему?» — объяснить через правила.
4. Не перегружать чат. Описание — коротко, по делу.
5. Предлагать конкретное действие, не ждать «что делаешь?».
6. Все изменения листов — **только через инструменты**, не прямая запись в файл.
7. Если правил не хватает (крайний случай) — принять решение в духе игры и записать в лог.

## Как skills подгружаются

1. Агент получает сообщение
2. Анализирует задачу
3. Если попадает под скил — загружает его инструкцию (из `masters/<id>/skills/`)
4. Следует инструкции скила, используя инструменты

Скилы — это `.md` файлы которые Builder создал при настройке.

## Иерархия принятия решений

```
Сообщение от админа / игрока
    │
    ▼
System prompt (кто я, задача, ограничения)
    │
    ▼
Понять задачу → загрузить подходящий skill
    │
    ▼
Skill: используй инструменты X → Y → Z в этом порядке
    │
    ▼
Agentic loop: вызов инструмента → результат → думаю → ...
    │
    ▼
Ответ в чат
```

## Отличие от обычного агента

Обычный агент: system prompt + tools + agentic loop.

Наши агенты:

- **Builder** — создаёт структуру для другого агента (программирует не кодом, а файлами, шаблонами, скилами)
- **Game Master** — работает в структуре созданной Builder'ом; его скилы и инструменты частично динамические (зависят от игры)
- Оба работают с одним интерфейсом платформы (файлы, чат, рендерер)
