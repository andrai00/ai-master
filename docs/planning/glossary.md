# Глоссарий проекта

> **Обновлено:** хранение в Prisma + SQLite. Добавлены режимы и категории данных.

## Термины

| Термин | Значение |
|---|---|
| **Builder** | Агент 1. Изучает правила, создаёт структуру мастера. Работает с админом в режиме разработки. Имеет два под-режима: Brain (настройка правил) и Memory (работа с игровыми данными) |
| **Game Master** | Агент 2. Ведёт игру, используя структуру от Builder'а. Работает с игроками в режиме игры |
| **Админ** | Человек который настраивает мастера (создаёт/правит). В режиме Memory может править игровые данные вручную |
| **Игрок** | Человек который играет (не трогает правила, не создаёт листы сам) |
| **Мастер** (конфигурация) | Вся структура созданная Builder'ом: глоссарий, мозг, шаблоны, скилы, формулы. Одна игра = один мастер. |
| **Игра** | Экземпляр мастера. Имеет название, владельца-админа, список допущенных игроков, режим (development/game). |
| **ActiveGame** | Таблица-синглтон (одна запись `id="singleton"`). Хранит `currentMasterId` — какая игра сейчас активна для всех. Меняет только админ. |
| **GameAccess** | Таблица связей игроков с играми. Определяет к каким играм у игрока есть доступ. |
| **Режим разработки** (development) | Режим мастера в котором Builder и админ создают/правят правила. Игроки не подключены. Меняются glossary и brain. |
| **Режим игры** (game) | Режим мастера в котором Game Master ведёт игру с игроками. Glossary и brain read-only. Меняются game_hidden и game_visible. |
| **Brain mode** (Builder) | Под-режим Builder внутри development. Чтение/запись glossary+brain. Память игры недоступна. |
| **Memory mode** (Builder) | Под-режим Builder внутри development. Чтение всех категорий, запись game_hidden+game_visible. Glossary+brain read-only. Для ручных правок игрового состояния и миграций. |
| **Glossary** (категория) | Исходные правила, загруженные админом. Хранятся почти 1-в-1. Меняются только в development (Brain mode). |
| **Brain / Мозг** (категория) | Инструкции ИИ для самого себя: как вести игру, порядок создания персонажа, обработка ситуаций. Создаётся Builder'ом. Меняется только в development. |
| **Game hidden** (категория) | Скрытые заметки, планы, идеи Game Master'а. Пишутся во время игры. Игроки не видят. |
| **Game visible** (категория) | Данные доступные игрокам: листы персонажей, общая информация. Каждый игрок видит свои (playerId). Управление через чат. |
| **Migration summary** | Документ (brain, type=migration_summary) который Builder создаёт при переключении dev→game. Описывает что изменилось в правилах. Game Master читает и решает что обновить у игроков. |
| **Дамп мастера** | Экспорт всей структуры правил игры (без данных игроков и чатов). Для шеринга и бэкапа. |
| **Composite-документ** | Документ собранный из слоёв (раса + класс + уровень + ...) |
| **Слой** (composition layer) | Один кусок composite-документа (эльф, вор, 3 уровень) |
| **Три слоя данных** | Данные + композиция + тело .md (видимое) |
| **Скрытые маркеры** | `<!-- meta:... -->` в теле .md. Не видны игроку, парсятся рендерером |
| **Скил (skill)** | Загружаемая инструкция для агента под конкретный сценарий (brain-документ) |
| **Инструмент (tool)** | Функция которую агент вызывает: read_document, search_content, send_chat... |
| **Progressive disclosure** | Стратегия послойного чтения: метаданные → summary → полный документ → связи |
| **Семантический поиск** | Поиск по смыслу через эмбеддинги (в отличие от grep по ключевым словам) |
| **Сессия** | Один чат: game (общий), personal (личный), builder (настройка). Сквозная, без ветвления истории. Привязана к мастеру. |
| **Саммари** | Автоматическое сжатие истории чата для экономии контекстного окна. AI пишет при ~20 сообщениях, хранится как документ. |
| **История чата** | Полный лог сообщений. Доступна через кнопку «Показать всю историю» при прокрутке вверх — paginated view без поля ввода. |
